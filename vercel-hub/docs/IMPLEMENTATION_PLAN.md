# PrizeNine 자동 리뷰 영상 시스템 구현 계획

## 1. 최종 사용 방식

사용자는 어느 컴퓨터에서든 이 저장소를 열고 Codex에 아래처럼 입력한다.

> 이 상품으로 리뷰 영상 만들어줘: <상품 URL>

프로젝트에 포함된 Codex 스킬이 URL을 작업 파이프라인에 등록한다. 이후 시스템이 제품번호 선점, 상품 조사, 40초 콘티 작성, Topview 영상 생성, Google Sheet 갱신, 완료 메일 발송까지 수행한다.

## 2. 핵심 원칙

- 제품번호는 상품 정보를 Google Sheet에 먼저 입력한 뒤 A열 배열수식이 자동 부여한 값을 다시 읽어 확정한다.
- A:F의 사용자 상품 데이터는 보존한다.
- 가격, 할인율, 효능, 인증, 후기 수 등은 확인된 정보만 사용한다.
- 단점이 확인되지 않으면 허위 단점을 만들지 않고 `구매 전 확인사항`으로 표현한다.
- 40초 영상은 하나의 긴 생성 요청이 아니라 5~7개 장면으로 설계하고 Topview Canvas에서 조립한다.
- 모든 외부 작업은 재시도 가능해야 하며 같은 작업을 중복 생성하지 않는다.

## 3. 데이터 구조

기존 열:

| 열 | 값 | 관리 주체 |
|---|---|---|
| A | 제품번호 | 기존 `=ARRAYFORMULA(IF(B2:B="", "", ROW(B2:B)-1))` 수식이 자동 부여 |
| B | 카테고리 | 시스템 자동분류 |
| C | 상품명 | 시스템 정제 |
| D | 브랜드/제품설명 | 시스템 정제 |
| E | 파트너스 링크 | 사용자 입력 링크 보존 |
| F | 상품이미지 | 시스템 추출 또는 사용자 입력 |

결과 열:

| 열 | 값 |
|---|---|
| G | 영상URL |

기술 상태는 별도 `_jobs` 탭에 저장한다. 이 탭은 `job_id`, `제품번호`, `원본상품URL`, `상태`, `Topview task/board 식별자`, `콘티·대사 JSON`, `오류`, `생성/수정시각`, `메일발송시각`을 가진다. 따라서 공개 사이트가 읽는 상품 시트는 A:G로 단순하게 유지된다.

## 4. 처리 흐름

1. URL 접수
   - Codex 프로젝트 스킬 또는 관리자 화면에서 URL 1개를 받는다.
   - URL 형식과 지원 마켓을 검사한다.

2. 제품번호 인식
   - 먼저 빈 행의 B:F에 카테고리, 상품명, 브랜드/제품설명, 파트너스 링크, 상품이미지를 입력한다. A열은 쓰지 않는다.
   - Sheets append 응답의 `updatedRange`에서 추가된 행 번호를 얻고, 배열수식 계산이 끝난 뒤 해당 `A{행번호}`를 다시 읽는다. 값이 아직 없으면 짧게 재조회한다.
   - 읽은 제품번호를 작업 레코드에 저장하고 이후 콘티, 대사, CTA에 동일하게 사용한다.

3. 상품 조사와 정제
   - 상품 페이지에서 상품명, 브랜드, 이미지, 특징, 구성, 주의사항을 수집한다.
   - 서로 다른 근거가 있는 장점과 단점을 구분한다.
   - 카테고리와 마켓을 자동 분류한다.
   - 접속 제한 페이지는 사용자 제공 설명/이미지 또는 관리자 보완 대기 상태로 전환한다.

4. 약 40초 콘티 자동 작성
   - 0~4초: 문제 제기 또는 결과 중심 훅
   - 4~10초: 제품과 사용 상황 소개
   - 10~24초: 검증 가능한 장점 2~3개
   - 24~32초: 단점 또는 구매 전 확인사항
   - 32~37초: 추천 대상/비추천 대상
   - 37~42초: `프로필 링크에서 {제품번호}번을 검색하세요` CTA와 제휴 고지
   - 상품 특성에 따라 각 구간은 자동 조정하되 총 길이는 35~45초로 제한한다.

5. Topview 제작
   - 기본 보드, 최신 생성 설정, 잔여 크레딧을 확인한다.
   - 상품 이미지를 업로드하고 장면별 생성 자산을 준비한다.
   - 15초 초과·다중 장면이므로 Canvas 프로젝트를 생성한다.
   - taskId와 boardId를 즉시 저장하고 같은 식별자로만 폴링한다.
   - 실패 시 중복 제출하지 않고 재개 가능한 상태를 남긴다.

6. 결과 등록
   - 메인 상품 행 G열에 영상URL을 기록하고, 콘티·Topview 식별자·완료시각은 `_jobs`의 같은 제품번호 작업에 기록한다.
   - PrizeNine 사이트는 제품번호 검색과 파트너스 링크 이동에 바로 사용한다.

7. 메일 알림
   - `ready` 전환 시 1회만 발송한다.
   - 제목: `[PrizeNine] {제품번호}번 리뷰 영상 완성`
   - 본문: 상품명, 영상URL, 사이트 상품URL, 파트너스 링크, 실패/주의 메모.
   - 기본 구현은 Vercel + Resend로 하고, API 키가 없으면 Google Apps Script 메일 방식으로 대체할 수 있게 어댑터를 둔다.

## 5. 휴대 가능한 구성

- `.agents/skills/prizenine-review/SKILL.md`: Codex에서 자연어 한 줄 실행
- `scripts/setup.ps1`: Windows 새 PC 환경 검사 및 설정 안내
- `.env.example`: 비밀값 이름만 제공
- `docs/SETUP_NEW_PC.md`: Topview OAuth, Google 서비스 계정 공유, Vercel/메일 설정
- `docs/RUNBOOK.md`: 실행, 실패 복구, 중복 방지, 비용 확인
- 서버 API: 번호 선점, 작업 조회, 상태 갱신, 완료 메일
- 비밀값과 OAuth 토큰은 저장소에 커밋하지 않는다.

## 6. n8n 사용 여부

1차 구현에는 n8n을 넣지 않는다. Codex + Vercel API + Google Sheet + Topview MCP만으로 흐름이 단순하고 휴대하기 쉽다. 다수 상품 예약 실행, 시간대별 배치, 승인 단계, 여러 알림 채널이 필요해질 때 n8n을 선택형 오케스트레이터로 추가한다.

## 7. Luna Light 구현 순서

### 작업 A — 기반과 데이터 안정성

- 상품 행 추가 후 배열수식 제품번호 재조회 API
- 상품 시트 A:G 및 `_jobs` 작업 탭 매핑과 기존 데이터 호환
- 상태 전이 및 idempotency key
- 단위 테스트

### 작업 B — Codex 휴대형 스킬

- 한 줄 URL 접수 스킬
- 새 PC 설치 문서와 환경 검사 스크립트
- 비밀값 누락 시 정확한 안내

### 작업 C — 조사·콘티 생성기

- 상품 정보 정규화 스키마
- 근거/장점/단점/주의사항 구분
- 35~45초 타임라인과 한국어 대사 생성
- 제품번호 CTA 고정 검증

### 작업 D — Topview 작업자

- Canvas 생성·조회·재개
- taskId 저장과 중복 생성 방지
- 완료 영상URL 기록

### 작업 E — 알림과 관리자 화면

- 완료 메일 어댑터
- 작업 상태/재시도/콘티 확인 화면
- URL 1개 입력 폼

### 작업 F — 종단 검증

- 샘플 URL 1개로 번호 선점부터 메일 수신까지 검증
- 새 PC 설치 절차 리허설
- 실패 후 재실행 시 영상이 중복 생성되지 않는지 확인

## 8. 완료 기준

- URL 한 줄 입력 후 B:F가 등록되고 배열수식이 만든 제품번호가 자동 인식된다.
- 생성 대사에 같은 제품번호가 정확히 들어간다.
- 35~45초 리뷰 영상이 생성된다.
- 시트의 동일 행에 정제 정보와 영상 결과가 기록된다.
- 완료 메일은 정확히 한 번 발송된다.
- 다른 Windows PC에서 문서대로 설치해 동일하게 실행된다.
- 오류 후 다시 실행해도 새 제품번호나 Topview 과금 작업이 중복 생성되지 않는다.
