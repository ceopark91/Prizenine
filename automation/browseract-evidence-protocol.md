# PrizeNine BrowserAct evidence protocol

Run this in the chat worker on the user's configured `chrome-direct` browser. The executable is `C:\Users\park\.local\bin\browser-act.exe`; do not assume it is in PATH. A BrowserAct session shown by `session list` belongs to another conversation unless this run opened it. Never operate or close another run's session.

1. Read `browser list` once. Open one new, uniquely named session on the configured `chrome-direct` browser at the **exact queued Coupang product URL**. Do not search Coupang repeatedly or guess another item URL.
2. `wait stable`, then `state` once to identify the title, selected option, gallery and review region. Use fresh `state` before an index-based click. Avoid `get markdown`, full `get html` and full-page `state` output in worker logs.
3. Use targeted read-only `eval` or scoped `get text --selector` to obtain only: product title, Coupang product ID, selected option, current specs, seller-gallery image sources, review count, and two to four **body excerpts** (date, exact option, 25–160 character excerpt). Each excerpt should capture a concrete experience or drawback, not merely the review count or rating. Exclude reviews for a different color/model unless marked as such and excluded from claims.
4. Compare multiple reviews for contradictions. Seller specification outranks a review for product mechanics. Do not use isolated review claims about safety, sterilization, exact drying time, dramatic before/after results, or included accessories without product-detail corroboration. Preserve one honest drawback in `limitations` and in the `honest_limit_or_check` scene.
5. Save a compact JSON evidence object. Keep a human-readable one-line insight and short excerpt per review; do not store full page HTML or full review bodies in prompts/logs. Select one to three distinct **seller product** images only. Read each selected URL from the rendered seller gallery and verify HTTP image response. Never substitute customer photos, recommendation ads or unrelated models.
6. Read `automation/conti-quality-template.json`, produce 6–8 distinct scenes spanning 28–40 seconds, and run `validate-conti.mjs` through `persist-verified-product.mjs`. Source-backed claims only; CTA uses the PrizeNine internal number, never Coupang product ID. Model 1 may appear in intro/CTA only, preserving the selected product's geometry and color.
7. Verify Supabase readback, then close **only** this run's BrowserAct session. If browser access or a required review body fails, record the exact blocker. Do not invent facts or use stealth/proxy/CAPTCHA bypass.

Token discipline: return concise selected evidence, not the complete accessibility tree, markdown page, review body, DOM or network log. One focused page, a few targeted reads, one JSON output, one quality check, then stop.
